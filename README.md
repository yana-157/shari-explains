# Shari Explains

A static editorial website for law, politics, and world-event explainers, with a local Post Studio. The public website has **no backend, database, login system, or npm dependencies**. Topic requests go to Google Forms.

## Start

Install Node.js 22 or newer once. Open this repository in Terminal, then run:

```sh
npm run studio
```

Open the Post Studio address printed in Terminal. **Save post** writes the post and its cover directly into the correct repository folder and rebuilds the local website. **Publish to live site** commits that post’s folder and any saved site settings and pushes it to GitHub. GitHub Actions builds and deploys the site.

See [Shari’s short publishing guide](docs/HOW-TO-POST.md).

For categories, global colors/text size, fonts, or page sections, see [Editing the site](docs/EDITING-THE-SITE.md). Everyday category and design changes are available in **Post Studio → Site settings & design**.

## Repository layout

```text
posts/                         One self-contained folder per article
  article-address/
    post.json                  Headline, date, text, category, sources
    cover.jpg                  Locally hosted cover artwork
    editorial-notes.md         Optional private-to-repo editorial context
src/                           Public website HTML, CSS, JavaScript
  shared/article.mjs           Article renderer used by both site and Studio
studio/                        Writing form and live preview
content/site.json              Site-wide links and settings
scripts/                       Build, local Studio server, validation
docs/                          Plain-language publishing guide
.github/workflows/pages.yml    Automatic build and GitHub Pages deployment
dist/                          Generated output; do not edit or commit
```

## Publishing setup

The repository uses `main` and GitHub Pages with **GitHub Actions** as its publishing source. The local Publish button expects `origin` to be `yana-157/shari-explains`, a normal authenticated Git setup, and no unrelated staged files. It never force-pushes. It preserves a local commit if the network push fails, so Publish can be retried after sign-in or synchronization.

For a new computer, clone this repository, install Node.js, and sign in through GitHub CLI (`gh auth login`, then `gh auth setup-git`) or use GitHub Desktop. The Studio runs only on `127.0.0.1`; its write endpoints are absent from the deployed static website. No GitHub token is stored in the website or browser.

The optional `.openai/hosting.json` identifies the private Sites preview. **The Studio’s Publish button updates GitHub Pages**, not that separate private snapshot.

## Article format

`post.json` is ordinary JSON, generated by the Studio. `body` is plain text: blank lines make paragraphs, `## Heading` makes section headings, `### Heading` makes smaller headings, `**text**` adds emphasis, and `- item` makes a list. Raw HTML is escaped. `sources` is an array of `{ "title": "…", "url": "https://…" }` objects. `status: "draft"` keeps a post out of the generated public site. Each folder name must match the record’s `id`.

Keep article addresses unchanged after publishing to preserve readers’ bookmarks. Changes to titles do not change existing addresses in the Studio.

## Initial archive and editorial review

Nine Instagram posts were reproduced as locally hosted cover images and transcribed article text, with their original captions and dates. They are marked as archival reproductions. They are not embeds, and the article UI does not redirect readers to Instagram.

The source text is retained as supplied, including dated claims and source errors. Per-post `editorial-notes.md` files record known transcription/source caveats for Shari to review. These notes and original-source URLs are excluded from the generated public article data. The South Park post’s original video clip is not included; its still-image text is reproduced. No professional credentials or contact email have been invented.

Design references: [Shari’s Instagram](https://www.instagram.com/shari_explainslaw/), [Rotten Mango’s episode archive](https://www.rottenmangopodcast.com/allepisodes), and [Leeja Miller’s about page](https://www.leejamiller.com/about-1), alongside the supplied sketches. Research-room links are general starting points, not claims that those sources substantiate every archived article.

## Google Form

The topic-request form is linked from `content/site.json` and the public page. It asks for a topic, optional context, and category; it does not collect email addresses or require a Google account. Responses stay in the owner’s Google Form. Form editing and response access belong to the Google account that created it; the website does not expose the editor link.
